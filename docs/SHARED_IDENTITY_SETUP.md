# Shared identity and persistence rollout

## What this branch implements
- PostgreSQL-backed accounts with scrypt password hashes and opaque server-side sessions (only the session digest is stored).
- HttpOnly, SameSite=Lax session cookie; a separate CSRF cookie/header check protects data writes and logout.
- Registration is opt-in and disabled by default.
- Per-account JSON sync endpoints for conversations, memory, artifacts, projects, and preferences. A namespace allowlist, 128 KiB per-item bound, optimistic version check, and user-scoped SQL prevent client-supplied user IDs from crossing accounts.
- The main interface exposes login/register/logout and syncs conversations between devices after authentication.

## Required Render setup before live use
1. Open the Elyntro web service's Environment page.
2. Set `ELYNTRO_DATABASE_URL` to the database's **internal** connection string from the Render Postgres Connect panel. Do not paste it into GitHub, chat, logs, or client-side JavaScript.
3. Keep `ELYNTRO_COOKIE_SECURE=true` in production.
4. Keep `ELYNTRO_REGISTRATION_ENABLED=false` until live DB smoke tests and abuse controls are in place. Enabling this variable makes public self-registration available.
5. Deploy this branch only after CI is green, then verify `/api/identity/me` returns 503 while the database is unconfigured and 401 when configured but logged out; create a test account, login, write/read/delete a test sync item, and verify a second account cannot read it.
6. Remove the database's public IP allowlist entries after confirming the web service uses the private network. The Render MCP connector cannot query the current database because its IP allowlist is empty; this is a useful secure default, not a reason to open it to the whole internet.

## Limitations / production gates
- The existing Render Free Postgres instance is temporary and expires on 2026-11-25. Use it for a short validation window only. A managed alternative such as Supabase Free currently advertises 500 MB Postgres, 50,000 monthly active users, and 1 GB storage, but free projects can pause after one week of inactivity and do not include automatic backups. The project owner must create/configure any external account; this repo does not contain credentials.
- Login has per-IP rate limits in the app process, not a distributed rate limiter. Public registration should remain disabled until email verification, account recovery, abuse monitoring, and a persistent shared rate-limit store are implemented.
- Existing local browser history is not automatically migrated unless the user signs in and the browser can reach the database. Test migration with a disposable account first.
- Provider API keys (Groq, search, ComfyUI) are external credentials and cannot be generated by this code. Add real keys directly to Render only after creating them in the provider account. Never commit them.
- The browser worker must be deployed as a Render Private Service from the Blueprint and given the same independently generated worker token on both services. Do not deploy it as a public web service. URL/DNS validation is defense in depth, not a network firewall; do not enable browsing of untrusted sites until egress blocking for loopback, private, link-local, metadata, and non-global destinations is enforced and tested at the network layer.
